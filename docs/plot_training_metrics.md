# Reproduce training figures

`src.Scripts.plot_training_metrics` creates loss curves, metric curves, and per-class validation figures from the project's exported metrics ZIP or a local `trainings` directory. It does not import PyTorch, load checkpoints, or run inference. All PNG and SVG files are generated by the same command, alongside their JSON data.

Install the optional plotting dependency:

```bash
python -m pip install -r install/requirements-analysis.txt
```

Run from the project root. Use the SHA-256 of the split used by the experiments:

```bash
python -m src.Scripts.plot_training_metrics \
  --input diagnostics/metrics.zip \
  --split-sha256 <split-sha256> \
  --output diagnostics/training_figures
```

`--input trainings` reads local run directories instead. `--data-only` exports JSON using only the standard library, without rendering. `--models image image-dinov3` restricts the output to specified model families; the default includes all five families: `image`, `image-dinov3`, `pose`, `pose-wide`, and `pose-attention`.

## Selection and reproducibility

By default, the script selects the run with the highest **pooled validation macro F1** in each family. Within that run it selects the earliest epoch reaching the maximum, matching the trainer's strict improvement rule. Run-name order breaks ties between equally scoring runs. This is validation-based experiment selection, not an estimate of final test performance. No test metrics file is read.

Selection is restricted to one split hash and one annotation hash. The script refuses mixed split versions unless `--split-sha256` is supplied. If multiple annotation versions remain, pass `--annotation-sha256` as well. If the data contains exactly one version, it can be inferred. Pose and image models may have different eligible sample counts even with the same split hash; these counts are retained in the exported configurations.

To pin the exact runs, pass `--selection` with a JSON file:

```json
{
  "split_sha256": "<split-sha256>",
  "annotation_sha256": "<annotation-sha256>",
  "models": {
    "image": "resnet-run-name",
    "image-dinov3": "dinov3-run-name",
    "pose": "mlp-run-name",
    "pose-wide": "wide-mlp-run-name",
    "pose-attention": "attention-run-name"
  }
}
```

The output includes `selection.json` with the resolved run names and hashes, so the next invocation can reproduce exactly the same selection:

```bash
python -m src.Scripts.plot_training_metrics \
  --input diagnostics/metrics.zip \
  --selection diagnostics/training_figures/selection.json \
  --output diagnostics/training_figures
```

An existing output directory is updated. Source files are read without modification. ZIPs are never extracted; member names are checked and manifest size/hash entries are verified for every configuration and metrics file read. When a ZIP has no manifest, the JSON explicitly records that manifest verification was unavailable. Local directories are per-file snapshots and can change while training is running.

## Figures and chart data

Each model has its own subdirectory containing PNG and editable SVG files:

- `loss`: training and validation cross-entropy across all logged epochs.
- `metrics`: training accuracy, validation accuracy, and pooled validation macro F1.
- `evaluation_metrics`: pooled validation, held-out-view, and unseen-moment macro F1 curves when available.
- `loss_windows`, `metrics_windows`, and `evaluation_metrics_windows`: additional pose-only figures, with the first 20 logged epochs and the remaining epochs in separate panels. Each panel uses its own Y bounds. Evaluation-group curves are included when available.
- `presentation_curves`: a slide-ready image with loss and score columns. Pose models have initial and later epoch rows; image models show their entire history. PNGs are 2304 × 900 pixels, intended for a 1152 × 450 area. Numeric X coordinates are the logged epochs, with round interior ticks and actual endpoints; these images avoid presentation software reinterpreting chart categories. Legends retain consistent train, validation, and macro F1 colors. These compact figures omit the selected-checkpoint marker.
- `class_f1`: per-class F1 at the selected checkpoint, with pooled, held-out-view, and unseen-moment series.
- `class_recall`: a heatmap with one row per class and columns for Overall, Held-out view, and Unseen moment. Each cell shows the exact number of correct predictions over its support, then recall as a percentage. Colors use a fixed 0–100% scale across models.
- `per_class`: precision, recall, and F1 for the pooled validation set.
- `per_class_held_out_view` and `per_class_unseen_moment`: precision, recall, and F1 for each evaluation group when available.
- `initialization_loss` and `initialization_metrics`: a **separate** source-training trajectory through the checkpoint used to initialize a later stage, when the source run is present and its metadata matches.

The dotted vertical line on the full-size curves marks the selected checkpoint. Curves are unsmoothed and use every complete logged record. Accuracy and F1 are rendered as percentages but stored as fractions in `chart_data.json`. Class plots align by class name and retain support counts in JSON. Group F1 scores are separate measurements; their average is not pooled macro F1.

Curve Y axes adapt to the observed values in each model, with padding and readable tick spacing. Every series in a chart shares the same bounds, and every epoch and finite value remains visible. Loss axes stay nonnegative; accuracy and F1 axes stay within 0–100%. The ranges can differ between models, so compare the axis labels when judging differences. Per-class charts retain their fixed scales.

For pose models, the additional window figures separate the rapid initial changes from later training. All logged records appear exactly once across the panels, without smoothing, overlap, or renumbering; their titles show the actual epoch ranges and explicitly note the independent Y scales. The dotted checkpoint line appears only in the panel containing that epoch. The full-history figures and image-model figures are unchanged. Use `--pose-initial-epochs 10` to separate the first 10 logged records instead, or `--pose-initial-epochs 0` to disable these additional figures. A run with 20 or fewer records has one panel containing its entire history, rather than an empty second panel. Separate initialization trajectories receive their own windows under `initialization_*_windows`.

The output root also contains `class_recall_image` and `class_recall_pose` in PNG and SVG. These combine the selected image or pose models as separate blocks, each with the same three validation columns. They use class recall (correct / actual examples of that class), not F1. A zero-support class is shown as `N/A` rather than as a measured 0%; missing evaluation groups also show `N/A`. Counts come from the confusion matrix diagonal when available, with row totals checked against class support and the resulting ratio checked against logged recall. Without a confusion matrix, correct counts are reconstructed only if the logged recall and support agree with an integer count.

`presentation_recall_image` and `presentation_recall_pose` show the same blocks in a compact 2304 × 1000 PNG canvas for slides. All presentation exports also have SVG versions and use a `#F6F8FA` background. Insert the PNG files directly into slides to preserve the labels and geometry. The reusable Python entry point `render_presentation_curves(data, output)` generates only these slide assets from an existing chart-data dictionary; `render_figures` and the normal CLI include them automatically.

`chart_data.json` has `schema_version: 1`, source hashes, selection rules, split and annotation hashes, and a `models` array. Each model contains:

- `model`, `display_name`, `run_name`, `selected_epoch`.
- `config` active at the selected epoch, `latest_config`, and all `config_events` for resumed runs.
- `best`, the complete selected validation metrics, including confusion matrix when logged.
- `epochs`, with `epoch`, `train_loss`, `val_loss`, `train_accuracy`, `val_accuracy`, `val_macro_f1`, `held_out_view_macro_f1`, and `unseen_moment_macro_f1`. Unavailable group values are `null`.
- `curve_y_axes`, with `loss`, `metrics`, and `evaluation_metrics` ranges. Each has `min`, `max`, and `major_unit`, in the same units as the epoch values. These bounds are exported with `--data-only` too and used directly by the PNG/SVG renderer.
- `curve_windows`, for pose models, with `key` (`initial` or `later`), `first_epoch`, `last_epoch`, the corresponding `epochs`, and independent `curve_y_axes`. This is an empty list for image models or when windows are disabled. The original `epochs` and full-history bounds remain available.
- `per_class` and `per_class_by_evaluation_type`, with class name, precision, recall, F1, and support.
- `class_recall_blocks`, with fixed `columns`, `column_labels`, and class `rows`. Each row has three `cells` containing `correct`, `support`, `recall`, `available`, `count_source`, `label`, and hexadecimal `fill`/`text` colors. Zero-support recall is `null`; unavailable groups also have `null` counts. This data can recreate the heatmap as editable presentation table cells.
- `checkpoint_provenance` and optional `initialization_source_training`. The latter contains its run name, configuration, source epoch, separate epoch series, and its own `curve_y_axes` and `curve_windows`.
- `files`, the relative figure paths, and `warnings`.

Root-level `files` lists the combined heatmaps. `figure_styles.class_recall` records the shared palette and scale; its cell colors are generated without importing Matplotlib, including with `--data-only`.

An `--init-from` stage keeps its own epoch numbering and is never silently concatenated with an earlier run. The initialization link is based on logged checkpoint provenance; exported metrics do not contain checkpoint bytes and cannot verify the actual weights. Resume histories with duplicate or out-of-order epochs are rejected. An unfinished trailing JSONL record is ignored and reported; an invalid completed record is rejected. Missing run metrics are listed in `skipped_runs`.

The script never averages across seeds or chooses a separate checkpoint for each class or evaluation group. All class results for a model come from the same checkpoint chosen by pooled validation macro F1.

## Checks

```bash
python -m unittest tests.test_plot_training_metrics
```

These tests cover split isolation, annotation versions, explicit selection, resume histories, class-name alignment, confusion-matrix/recall consistency, zero-support cells, initialization lineage, curve bounds, complete and disjoint pose windows, unchanged image data, incomplete logs, and ZIP integrity.
